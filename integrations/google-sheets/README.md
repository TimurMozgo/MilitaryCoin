# Google Sheets и Apps Script

Основная база — D1. Google Таблица — зеркало для учёта. Управляйте товарами и заявками в админ-панели Telegram-приложения.

Рабочая таблица: https://docs.google.com/spreadsheets/d/1wCPcFAoy2yHhqpPPall35FYa9pdTeCRJAPzAsCLSgBg/edit

Скрипт: https://script.google.com/home/projects/12SgieGXdXD98XuWrfn3ZLOJQEO2KeJsNsyZxM0WsBajSTZ-EVZ41FyJ_/edit

Владелец: kvitbloom@gmail.com. Четыре листа: Заказы, Состав заказов, Товары, Движение остатков. Чеки остаются приватными в магазине. В таблице хранится ID чека; просмотр — в админ-панели.

## Поток данных

Telegram Mini App → сервер магазина → основная база → Apps Script → Google Sheets.

После создания заказа, изменения товара или обработки заявки сервер отправляет накопленные изменения. Если Google недоступен, заказ остаётся сохранённым в базе, а неотправленные изменения — в журнале. Следующая отправка продолжает с подтверждённого курсора. Повторные запросы обновляют строку по ID и не создают дубликатов. Таблица не управляет доступом к админке.

## Настройка

1. Применить миграции 0000, 0001 и 0002. На Sites это выполняется при публикации.
2. Серверные переменные: SHEETS_SYNC_KEY — отдельный случайный секрет, SHEETS_WEBHOOK_URL — опубликованный Apps Script URL, заканчивающийся /exec.
3. В свойствах Apps Script указать SYNC_KEY с тем же значением. Код Code.gs установить в привязанный к таблице проект. Выполнить setupReceiver.
4. Опубликовать как веб-приложение: запуск от владельца таблицы, доступ «Все». Запросы без SYNC_KEY отклоняются. Код не предоставляет чтение заявок через публичный адрес.
5. Секреты хранить только в настройках окружения и свойствах скрипта. Токен приватного хостинга в Google не передаётся.

## Важные поля

Telegram ID, имя и username берутся из подписанных Telegram initData на сервере. Имя получателя и обязательный телефон заполняются клиентом. Telegram не передаёт телефон при открытии Mini App. В старых заявках имя Telegram может отсутствовать; оно не восстанавливается вымышленным значением.

## Восстановление

POST /api/shop/integrations/sheets/retry отправляет одну страницу очереди. Ответ сообщает ok, cursor, hasMore либо ошибку. Он не принимает содержимое заказов и не отдаёт персональные данные. Для текущего приватного Sites сначала действует внешний контроль доступа. Одновременные отправки защищены арендой блокировки в D1 на две минуты. Скрипт дополнительно использует LockService.

В свойствах Apps Script LAST_SUCCESS и LAST_ERROR показывают результат записи. На сервере settings содержит sheets_cursor, sheets_last_success и sheets_last_error. Для полного восстановления зеркала сбросить курсор в обоих местах. Журнал пока не очищается.

При переносе на другой хост нужны D1/R2 либо совместимые адаптеры и собственный фоновый вызов /api/shop/integrations/sheets/retry. В текущем коде основной источник данных остаётся база. Сам по себе push в GitHub не переносит хостинг и хранилища.
