# Магазин коллекционных монет · Telegram Mini App

Рабочий исходный проект: React / Vinext, сервер Cloudflare Workers, D1 (данные), R2 (фото и приватные чеки). Админ-панель доступна только пользователям с подтверждёнными Telegram ID 6088315974 и 1246079025. Авторизация проверяется сервером.

## Оформление

Тёмный графит, оливковые панели, песочные заголовки и оранжевые действия по референсу пользователя. Карточка: фото, название, цена за штуку и кнопка +, затем доступный остаток. Нажатие + добавляет одну монету и сразу открывает корзину. Название и логотип магазина пока не выбраны.

## Что реализовано

- Каталог и карточка товара с доступным остатком. Галерея с пролистыванием, окно «О монете», полноэкранные фотографии, закрытие крестиком / Escape / кнопкой Telegram «Назад».
- Корзина сохраняется на устройстве. Количество ограничено доступным остатком; при отправке сервер перепроверяет цену и количество.
- Предоплата 10% в гривнах, округлённая вверх до копейки; обязательный чек JPG/PNG/WebP/PDF, максимум 8 МБ. Реквизиты настраиваются администратором.
- Заказы сохраняются в БД. В профиле три последних заказа, отдельный экран всей истории с дозагрузкой.
- «В обработке» — оранжевый, «Принято» — зелёный, «Отклонено» — красный, обязательная причина видна покупателю.
- Только Telegram ID 6088315974 и 1246079025 имеют серверный админ-доступ. Редактор товара: название, цена, доступный остаток, описание, год, номинал, до 10 фото, выбор главного фото, скрытие товара.
- Атомарный резерв при отправке заявки. Отклонение возвращает резерв ровно один раз. Принятие не возвращает монеты в продажу. После обработки статус окончательный в текущем интерфейсе.
- Повторная отправка одного запроса не создаёт дубликат. Один загруженный чек используется для одного заказа. Проверка Telegram HMAC и возраста сессии; чужая история и чужие чеки недоступны.
- Плавные переходы и окна, поддержка reduced-motion и безопасных отступов телефона.

## Перед реальными заказами

1. Создать бота в BotFather. Сохранить TELEGRAM_BOT_TOKEN как серверный секрет и TELEGRAM_BOT_USERNAME как серверную переменную. Токен нельзя добавлять в браузерный код или коммитить.
2. У проекта Sites первоначально приватный доступ. Для клиентского запуска в Telegram необходим публичный доступ к сайту либо отдельное совместимое размещение, без внешнего входа ChatGPT. Подключить HTTPS URL в BotFather как Mini App / кнопку меню.
3. Зайти из Telegram под одним из двух администраторов. В «Реквизиты» добавить получателя и платёжные реквизиты. У первой монеты указать реальный доступный остаток: сейчас он намеренно равен 0, потому что количество не сообщено. Цена 130 ₴ взята из карточки продавца, её можно изменить.
4. Проверить реальные операции из Telegram: заказ, чек, принятие, отклонение и просмотр истории. До подключения бота эти действия закрыты, каталог доступен.

Фото и исходные сведения первой монеты: https://prom.ua/ua/p2831688904-dshv-desantno-shturmovye.html . Использованы три фотографии из указанной карточки; никаких вымышленных заказов или остатков в БД нет.

## Проверка и запуск

Node.js 22.13+; зависимости установлены. `node scripts/run-framework.mjs build` собирает проект. `node node_modules/typescript/bin/tsc --noEmit` проверяет типы. `node --test tests/shop.test.mjs` проверяет авторизацию, резерв, возврат остатка, дубли, цену и историю.

После сборки применить локальную миграцию один раз: `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_shiny_bishop.sql`. Затем `node scripts/run-framework.mjs dev`. Локальная БД отделена от опубликованной. При размещении через Sites миграции применяет платформа.

## Следующий этап

Подготовлена интеграция Google Sheets через Apps Script: см. integrations/google-sheets/README.md. Сервер автоматически отправляет сохранённые изменения в настроенный приёмник. Онлайн-эквайринг не используется: чек проверяется человеком. Если заказ отклонён после фактической оплаты, возврат денег выполняется магазином отдельно; статус не инициирует банковский возврат.

До отправки заявки содержимое корзины не резервируется. Если остаток закончится во время оплаты, сервер отклонит отправку и попросит обновить корзину; для такого случая необходима договорённость магазина с покупателем о возврате или замене. Для удержания остатков до перевода потребуется отдельный резерв с таймером.
